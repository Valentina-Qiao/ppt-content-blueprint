# ppt-content-blueprint

> 内容层 Skill：把一份内容文档拆成答辩/汇报 PPT 的**逐页内容蓝图**。只决定“讲几页、每页讲什么、逻辑怎么排”，不绑定任何视觉模板，也不写 HTML/CSS。

- 导航入口：[presentation-slides-skills](https://github.com/Valentina-Qiao/presentation-slides-skills)
- 配套表现层：广州南方学院模板用 [gznf-html-slides](https://github.com/Valentina-Qiao/gznf-html-slides)；任意 16:9 PPTX 模板用 [pptx-stage-slides](https://github.com/Valentina-Qiao/pptx-stage-slides)

## 它的特长

- **内容与样式彻底解耦**：产物是纯文本蓝图，换任何模板都能复用，不必重想逻辑。
- **一页一论点、结论先行**：标题写成结论句，每页 2–4 个要点支撑，贴合 15–25 秒口播节奏。
- **内置页型库**：封面/目录/背景/文献/方法/技术路线/实验设计/进度/预期成果/结论等 13 类页，各自“放什么、不放什么”一目了然。
- **关系判定决策表**：明确区分并列/流程/因果/对照/组成，从根上避免“并列模块误加因果箭头”这类高频错误。
- **数据可追溯纪律**：每个数字强制标国别·范围·年份·来源·口径，专业名词附解释，材料没有的不臆造。

## 负责解决什么问题

当你拿着论文、开/结题报告、方案或汇报材料（md/word/pdf）却卡在：不知道分几页、每页堆整段文字、讲不清逻辑主线、把并列维度画成因果链、数据没来源、预期“成果”和“效果”混为一谈——这个 Skill 把“读材料 → 拆页 → 排逻辑 → 选表达元素”的判断固化成标准流程，输出可直接交给表现层制作的逐页蓝图。

## 什么场景适合用

- 要做答辩/汇报/路演 PPT，先需要一份靠谱的逐页大纲与每页重点。
- 同一套内容未来可能换多套模板，想让内容结构与皮肤分离。
- 材料信息密集，需要判断哪些上页、哪些合并、数据怎么标注、卡片/时间轴/图表怎么选。
- 单独使用即可拿到大纲；要成品 HTML/PDF 时，把蓝图交给 B 或 C。

**不适用**：不管配色字体、不写 HTML/CSS、不负责视觉还原——那是 B/C 的职责。

## 工作流（5 步）

1. 读材料，抽四类要素：主线论点、分论点/章节、证据数据、专有名词与方法；缺料不编造，合并页面或向用户要材料。
2. 定叙事主线与页数密度：答辩 3–5 分钟约 12–16 页，按“封面+目录+章节过渡+内容+收尾”组织。
3. 一页一论点、结论先行，金字塔结构支撑。
4. 先判模块关系再决定能否用箭头（见下“常见问题”）。
5. 标重点与表达元素、控制信息密度，按 `references/blueprint-template.md` 字段逐页输出蓝图。

## 常见问题与解决方案

- **内容太多一屏放不下？** 不靠缩小字号硬塞；优先拆页或合并同主题，模块区横向不超过 3 分区、纵向不超过 3 块，并列卡 3–5 个为宜。
- **几个并列方面能不能加箭头？** 不能。同层级可换序的维度（如知识/态度/意愿）一律等高独立成卡、卡间禁箭头；箭头只用于有先后的流程，或卡片内部“证据→启示”。拿不准默认按并列并请用户确认。
- **材料里找不到某个数据怎么办？** 不目测、不凑整、不编造；在蓝图标注缺口，合并相关页或向用户索要出处。
- **“预期成果”和“预期效果”老混？** 必须拆两件事：成果是做完手里有的“物”（题库/工具/数据集/论文）；效果是用了之后发生的变化（得分提升、组间差异、参考价值）。材料分两处写时两处都要收。
- **未来/规划项怎么表达？** 用虚线框并明确标注“非本期实现/未来工作”，不得画成已完成。
- **用户说的“第 N 页”对不上？** 自然序号与方块页码可能不一致，按实际页名与用户确认，不臆断合错页。
- **需要精简长文案？** 只重组不阉割；删改前必须先与用户确认，用户明确保留的一字不动。

## 铁律摘要

只重组不阉割；并列禁箭头；一页一主题；数据可追溯；对称等高不孤卡；边界（未来工作）写清楚。
